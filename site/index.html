Forja

An open-source backend in one executable.

Forja keeps data in a SQLite file, signs users in, and serves an admin panel from the same process. The HTTP API follows PocketBase, so PocketBase's Python client already works against the routes that exist.

0.0.3, early development

What runs in 0.0.3.

One SQLite file

The database is a single data.db in WAL mode. The process opens that file itself.

Email and password

Superuser login, plus accounts with verification, password reset, and email change. Mail prints to the console. SMTP is not in this version.

Records and rules

List, create, read, update, and delete, with filters, sorting, pagination, and access rules, in PocketBase's request shape.

Admin at /_/

Sign in, then list, create, edit, and delete records. The collection editor is not in this version.

Quick start

Rust stable is enough. The server listens on 127.0.0.1:8090 and writes ./forja_data.

git clone https://github.com/iramarfalcao/forjabase.git
cd forjabase
cargo run -p forja -- superuser upsert admin@example.com 'a-strong-password'
cargo run -p forja -- serve
curl http://127.0.0.1:8090/api/health

Clone and run.

There is no published binary and no server image yet. Clone the repository, create a superuser, and start the server on port 8090.

Version 0.0.3, early development.

Version 0.0.3 is what you can run today: collections, records, account email flows, and the record admin, on SQLite. PocketBase's Python client was checked against it on 21 October 2026.

Still ahead: relations and expand, files, realtime, the collection editor, OAuth, several projects on one instance, WASM extensions, generated SDKs, and published binaries. The order is in the repository plan. 1.0.0 waits until the API stays stable.
